# OceanMail Decision Index

Accepted decisions preserve rationale. Later decisions may supersede earlier ones; history is not rewritten.

Organization-level decisions are now authoritative in [`OceanMail/oceanmail-project`](https://github.com/OceanMail/oceanmail-project). This index remains the historical/current index for Desktop/client decisions recorded here.

| Decision | Status | Summary |
|---|---|---|
| [0001](0001-documentation-and-repository-authority.md) | **Program-authority assignment superseded 2026-09-11** | Originally made this repository the cross-repository documentation authority. `OceanMail/oceanmail-project` now owns organization-level authority; the component-ownership and explicit-supersession principles remain valid. |
| [0002](0002-client-station-server-product-model.md) | Accepted, partially superseded by 0005 | Separate Client, autonomous Station, and Server; treat Lite/Full primarily as capability/deployment profiles rather than separate applications. Decision 0005 supersedes the standalone/custom-client implementation assumption while preserving component separation. |
| [0003](0003-hermes-upstream-first-communications-foundation.md) | Accepted | HERMES/Mercury is the upstream-first 0.2 communications foundation; BEMPIC/M4P remain off the critical path. |
| [0004](0004-grid-accounting-and-relay-credit.md) | Accepted | Ordinary constrained-link OMail requires recipient selection; sender pays send quota, receiver pays receive quota, relays pay no user Grid quota, Stations still meter/log all relevant work, eager-relay credit goes to the registered vessel or captain account, and numeric/economic values are mutable Server-controlled service policy. |
| [0005](0005-thunderbird-client-foundation.md) | Accepted, shell details partially superseded by 0007; mobile portion superseded by 0006 | OceanMail Desktop is built on a pinned Thunderbird foundation with a mandatory OceanMail extension, OceanMail-owned behavior/branding, no general-purpose mail-account experience in 0.x, custom packaging, and strict coexistence with stock Thunderbird. |
| [0006](0006-desktop-ux-and-platform-independence.md) | Accepted, shell implementation partially superseded by 0007 | The accepted 0.1 prototype is the UX reference for Thunderbird-based OceanMail Desktop; the Desktop extension must remain Windows/macOS/Linux portable, while mobile is deferred as later separate iOS/Android development after the Desktop experience matures. |
| [0007](0007-native-thunderbird-shell.md) | Accepted | Thunderbird's native Spaces toolbar/application chrome is the single OceanMail Desktop shell: Mail/Calendar/Contacts are native Thunderbird foundations modified for OceanMail, Chat becomes/launches OChat, Station and other OceanMail-specific views integrate into native chrome, and no second primary navigation rail is permitted. |
| [0008](0008-account-scoped-mail-views-and-native-iconography.md) | Accepted | Available OMail is an account-scoped pseudo-folder/view inside native Mail, with per-account retrieval/budget state; OceanMail-added native-chrome icons must use Thunderbird's monochrome, theme-aware visual grammar rather than fixed-color extension artwork. |
| [0009](0009-ordinary-mail-scheduling-and-importance.md) | Accepted; hierarchy superseded 2026-09-21 | Emergency/Ordinary, Important-as-metadata, and recipient intent remain accepted. [Project ADR-008](https://github.com/OceanMail/oceanmail-project/blob/main/docs/decisions/ADR-008-four-band-scheduling-and-channel-use.md) defines Bands 0–3, capped control/route exception, remaining-time local/relay payload, and unreserved shared broadcasts. |
