# OceanMail 0.1 Documentation Migration Inventory

- **Status:** Active migration audit
- **Source:** the earlier 0.1 design
- **Target generation:** OceanMail 0.2

This inventory prevents wholesale copying of the 0.1 documentation tree. Classification describes what should happen to the **information**, not necessarily the source file.

## Classification vocabulary

- **REWRITE/CARRY** — important accepted behavior should become current 0.2 documentation, rewritten against current Client/Station/Server/HERMES boundaries.
- **MERGE** — useful material should be consolidated into a broader 0.2 document rather than retaining a dedicated file.
- **RESEARCH** — preserve as prior art/future design material; not active product authority.
- **HISTORICAL** — historical context only; not a current implementation requirement.
- **SUPERSEDED** — architecture/policy replaced by 0.2; retain only as history/rationale.

## 0.1 work reports

All files under `docs/work-reports/` are **HISTORICAL** by default.

They remain valuable for:

- provenance;
- exact implementation/test evidence;
- failures and recovery history;
- rationale that may need later investigation.

They are not copied into active 0.2 docs. A specific finding may be extracted only when it materially informs a current design or decision.

Source reports currently include the BEMPIC object profile, interactive prototype, v0.1 mail slice, owner UI refinement, transfer planner core, and v0.2 HERMES-transition work reports.
